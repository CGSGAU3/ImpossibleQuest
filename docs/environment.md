# Окружение и запуск

Рабочая версия Python: 3.11.15, macOS arm64. Команды для Windows приведены
ниже, но в этом комплекте на Windows не запускались. `requirements-test.txt`
содержит снимок проверенных зависимостей. Это список версий без хешей пакетов,
он не гарантирует одинаковый результат на любой платформе.

## Установка

Из корня проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt
python -m pip install '.[test]'
python -m pip check
python -m pytest -q
python -m quest_bot
```

В PowerShell первые две команды заменяются на:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```

После применения каждого пакета повтори `python -m pip install '.[test]'`.
По умолчанию команда `python -m quest_bot` только проверяет карту и не обращается
к Telegram. Другую карту можно передать через `--quest path/to/quest.json`.

## Настройки бота

Настройки читаются из переменных окружения. `.env` автоматически не загружается.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| BOT_TOKEN | Токен согласованного тестового бота | Обязателен для `--serve` |
| TRANSPORT | `webhook` или отдельный демонстрационный `polling` | webhook |
| WEBHOOK_BASE_URL | Внешний HTTPS-адрес без параметров URL | Обязателен для webhook |
| WEBHOOK_SECRET | Секрет проверки запросов Telegram, 1–256 букв, цифр, `_` или `-` | Обязателен для webhook |
| DATABASE_URL | URL SQLite для асинхронного драйвера | sqlite+aiosqlite:///quest.db |
| BIND_HOST | Локальный адрес HTTP-сервера | 127.0.0.1 |
| PORT | Локальный порт HTTP-сервера | 8080 |
| QUEST_PATH | Внешний JSON, если не нужна карта из пакета | Карта пакета |
| RULES_PATH | JSON с настройками игровых правил | Настройки Rules |
| LOG_PATH | Файл журнала | quest.log |

Путь webhook: `/telegram/webhook`. Перед приложением нужен HTTPS reverse proxy,
который передает этот путь на BIND_HOST и PORT. Полный внешний URL получается
из WEBHOOK_BASE_URL и `/telegram/webhook`. Заголовок секретного токена проверяет
aiogram. Не добавляй к WEBHOOK_BASE_URL query или fragment.

После задания настроек запусти:

```sh
python -m quest_bot --serve
```

Webhook соответствует HLD. Для отдельной локальной демонстрации можно явно
задать TRANSPORT=polling. Это отклонение от основного режима, его нужно
согласовать перед сдачей. Перед переключением действующего бота с webhook на
polling нужно отдельно убрать его webhook, приложение не делает это само.

Только один экземпляр приложения должен работать с одним токеном и БД:
блокировки пользователей находятся в памяти процесса. Не запускай тестовый
экземпляр с токеном уже работающего бота. Никакой сервер в рамках подготовки
комплекта не развернут, настоящий Telegram здесь не проверялся.

## Что проверять

- `python -m pytest -q` запускает локальные проверки без настоящего Telegram.
- `python -m pip check` проверяет совместимость установленных зависимостей.
- При запуске без BOT_TOKEN режим `--serve` должен завершиться с понятной ошибкой.
- При неверной карте проверка должна завершиться до настройки Telegram.
- При остановке закрываются фоновые задачи, SQLite engine и сессия Bot.

SQLite создается при первом запуске. В ней хранятся пользователи, сессии,
открытые концовки и один чекпоинт на пользователя. При ошибке чтения или записи
сессия временно остается в памяти, игрок получает предупреждение, `/save`
и `/load` недоступны. Следующая успешная запись восстанавливает постоянное
хранение. Перезапуск процесса во время отказа теряет еще не записанный прогресс.

Чекпоинт сохраняет сцену и флаги. История секретного кода и активная мини-игра
в него не входят. В бою и мини-игре save/load запрещены.

Журнал по умолчанию имеет уровень INFO. Записываются запуск, остановка,
первое открытие концовки и ошибки хранилища. Файл ротируется при 2 МБ,
сохраняются три предыдущих файла. BOT_TOKEN и WEBHOOK_SECRET не журналируются.

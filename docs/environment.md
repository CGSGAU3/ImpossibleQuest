# Окружение и запуск

Проекту нужен Python 3.11 или новее. На macOS или Linux из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[test]'
python -m pip check
python -m pytest -q
python -m quest_bot
```

В PowerShell вместо первых двух команд:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```

Для установки версий из снимка окружения выполни
`python -m pip install -r requirements-test.txt` перед установкой проекта.
Команды для Windows приведены для справки. Локальные проверки этого набора
проводились на macOS.

## Сборка и проверка карты

```sh
python -m pip wheel --no-deps --wheel-dir dist .
python -m quest_bot --quest path/to/quest.json
```

Первая команда кладет wheel в `dist/`. Внутри wheel есть карта `quest.json`.
Вторая проверяет отдельно переданный JSON. Если оставить просто
`python -m quest_bot`, команда проверит встроенную карту. Для этих проверок
токен Telegram не нужен. Если поменял исходники и проверяешь установленный
пакет из другой папки, установи обновленный проект еще раз.

## Запуск Telegram-бота

Бот берет параметры из переменных окружения. Файл `.env` сам не загружается.

| Переменная | Для чего нужна | По умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен тестового бота | Нужен для `--serve` |
| `TRANSPORT` | `webhook` или `polling` | `webhook` |
| `WEBHOOK_BASE_URL` | Публичный HTTPS-адрес без query и fragment | Нужен для webhook |
| `WEBHOOK_SECRET` | Секрет webhook, от 1 до 256 символов `A-Z a-z 0-9 _ -` | Нужен для webhook |
| `BIND_HOST` | Адрес, на котором слушает приложение | `127.0.0.1` |
| `PORT` | Порт приложения | `8080` |
| `DATABASE_URL` | URL базы SQLite | `sqlite+aiosqlite:///quest.db` |
| `QUEST_PATH` | Путь к другой карте JSON | Карта из пакета |
| `RULES_PATH` | Путь к JSON с настройками механик | Значения из `Rules` |
| `LOG_PATH` | Файл журнала | `quest.log` |
| `LOG_LEVEL` | Уровень сообщений квеста, например `DEBUG` | `INFO` |

Для отдельного тестового бота без публичного адреса задай токен в окружении и
выполни на macOS или Linux:

```sh
TRANSPORT=polling python -m quest_bot --serve
```

В PowerShell задай `$env:TRANSPORT = "polling"` и выполни
`python -m quest_bot --serve`. При запуске polling приложение снимает старый
webhook этого бота, сохраняя очередь обновлений. Один токен и один файл базы
использует один запущенный экземпляр.

Основной режим по HLD использует webhook. HTTPS-прокси должен передать
`/telegram/webhook` на `BIND_HOST:PORT`. Бот зарегистрирует полный адрес из
`WEBHOOK_BASE_URL` и `/telegram/webhook` после запуска HTTP-сервера. Telegram
передает секрет в заголовке, aiogram сверяет его. После настройки окружения
выполни `python -m quest_bot --serve`.

## Данные и диагностика

При первом запуске создается SQLite. В ней хранятся пользователи, текущие
сессии, открытые концовки и чекпоинты. В чекпоинте остаются сцена и флаги.
На сцене 45 `/load` запускает новый пятиминутный отсчет, а обычный `/start`
сохраняет прежний срок.
В бою и мини-игре `/save` и `/load` недоступны. При отказе базы игра
продолжается в памяти, команды сохранения и загрузки временно отключаются.
После восстановления связи приложение снова записывает состояние. Если
перезапустить процесс во время сбоя, изменения из памяти пропадут.

В журнале можно посмотреть запуск и остановку, открытия концовок и ошибки
хранилища. Файл меняется при размере около 2 МБ, остаются три предыдущих файла.
Если файл недоступен, сообщения идут в stderr. Для ручного демо используй
отдельную базу и тестового бота.

# Невозможный квест

Telegram-бот с текстовым квестом для ТРКПО. Сейчас есть пакет, зависимости,
модели данных и загрузка карты с проверкой ошибок. Игровые правила, БД и работа
с Telegram будут добавлены отдельными задачами. Команда запуска проверяет карту
и выводит число сцен и концовок. Токен не нужен, сетевых запросов нет.

## Установка и проверка

Нужен Python 3.11 или новее. Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
python -m quest_bot
python -m pytest -q
```

В Windows вместо первых двух команд:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```

Тест запускает установленный пакет из временного каталога. Так проверяется,
что для запуска не обязательно находиться в папке с исходниками. Остальные
проверки охватывают корректные карты, обязательные поля, ссылки и ошибки файлов.
Это еще не проверка прохождения квеста или работы бота.

Зависимости выбраны по HLD: aiogram, SQLAlchemy, SQLite через aiosqlite и Pydantic.
aiohttp нужен для webhook. Версии пока заданы диапазонами в `pyproject.toml`.

## Карта и модели

Исходная карта находится в `quest_bot/quest.json` и входит в устанавливаемый
пакет. Это копия полученного JSON без изменения содержимого. По умолчанию
загрузчик читает ее через `importlib.resources`. Другую карту можно проверить так:

```sh
python -m quest_bot --quest path/to/quest.json
```

При ошибке файла, JSON, полей или ссылок программа пишет причину в stderr
и завершается с ненулевым кодом. В сообщении есть путь и, для ошибок сцены,
ее идентификатор. Сцены боя с `next: null` допустимы, если на них ссылается
переход `battle`. Для Lost проверяются только ссылки, заданные в самой карте:
правила исходов будут добавлены в задаче мини-игры.

`load_content()` возвращает `Quest`: `start`, `secret_ending`, словарь `scenes`
и каталог `endings`. Формат сцен и выборов описан в `models.py`. Там же есть
`State` с текущей сценой, флагами, историей и данными активного режима. Это
предложение общего формата сессии для следующих задач, его еще нужно согласовать
с остальными участниками. Методов изменения состояния и сохранения в нем нет.

## Работа с задачами

[Задачи](https://github.com/CGSGAU3/ImpossibleQuest/issues) и
[доска](https://github.com/users/CGSGAU3/projects/2).

- А: игровая логика и контент.
- Б: Telegram и пользовательские сценарии.
- В: хранение и запуск.

Перед началом назначаем себя в Assignees и переводим задачу в In progress.
Для задачи с изменениями кода создаем отдельную ветку, например
`feature/1-content-loader`. Пока каркас не слит, стартовые ветки создаем от
`chore/project-skeleton`. Если нужна другая еще не слитая задача, ветку создаем
от ее ветки и указываем зависимость в PR.

На одну задачу открываем один PR. В описании нужны ссылка на задачу, требования
FS, разделы HLD и команды проверки. PR проверяет другой участник. В main напрямую
не коммитим, слияния оставляем на финальный этап и выполняем в порядке
зависимостей. После слияния базового PR обновляем базу следующего на main.
Организационным задачам без правок файлов ветка не нужна.

Задача готова, когда выполнены ее требования, проверки проходят, приложение
запускается и PR одобрен другим участником и слит в main. До слияния одобренный
PR остается на доске в In review. Для организационной задачи достаточно
выполнить ее критерии и проверить результат.

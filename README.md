# Невозможный квест

Telegram-бот с текстовым квестом для ТРКПО. Приложение разделено на игровую
логику, Telegram-интерфейс и хранение. Карта лежит в `quest_bot/quest.json`,
загружается отдельно от кода и проверяется перед запуском.

В подготовленной версии есть переходы по сценам, флаги, бой, Drunk, Lost,
прогресс концовок, сохранение сессии и чекпоинт. Проверки выполнялись локально
с подменой Telegram. Работу настоящего бота и демонстрацию команда еще должна
проверить отдельно.

## Установка и проверки

Нужен Python 3.11 или новее:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[test]'
python -m pip check
python -m pytest -q
python -m quest_bot
```

В Windows первые две команды:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```

Обычный запуск только проверяет карту и выводит число сцен и концовок,
сетевых запросов нет. Другую карту можно передать через
`python -m quest_bot --quest path/to/quest.json`. Настройки настоящего запуска
описаны в [инструкции окружения](docs/environment.md). Команда
`python -m quest_bot --serve` запускает бота только после задания этих настроек.

Карта включается в wheel вместе с пакетом. Ее содержимое не изменено;
`.gitattributes` сохраняет исходные окончания строк. Некорректный JSON,
неверные поля и ссылки останавливают запуск с указанием причины.

## Части проекта

| Часть | Файлы | Ответственный |
|---|---|---|
| Игровая логика и контент | models, content, story, flags, battle, drunk, lost, minigames | Владимир, dcfrqb |
| Telegram и пользовательские команды | application, endings, telegram_interface | Андрей, CGSGAU3 |
| Хранение и запуск | storage, sessions, checkpoints, bootstrap, logging_config | Костя, DreamForgerGD |

`State` описывает общие данные сессии, а `Rules` содержит настройки механик.
Изменения этих форматов согласуются с владельцем игровой части. Время и
случайность передаются в движок извне. В тестах используются отдельная SQLite
и подмена Telegram; настоящие пользовательские данные для тестов не нужны.

## Задачи, ветки и PR

[Задачи](https://github.com/CGSGAU3/ImpossibleQuest/issues) и
[доска команды](https://github.com/users/CGSGAU3/projects/2).

1. Назначь себя в Assignees и переведи взятую задачу в In progress.
2. Создай отдельную ветку под задачу, например `feature/15-storage`.
3. Если задача зависит от еще не слитой части, начни ветку от ее согласованной
   ветки и укажи зависимость в PR. В описании должно быть видно, какие изменения
   относятся именно к твоей задаче.
4. Прочитай подготовленные изменения, проверь их по FS/HLD, внеси нужные правки
   и запусти тесты. Затем сделай свой коммит и открой один PR на задачу.
5. Укажи ссылку на задачу, ID требований, разделы HLD, команды и результаты
   проверок. Другой участник должен проверить и одобрить изменения.

Напрямую в main не коммитим. Пока команда не решила иначе, слияния оставляем
на финальный этап. Сначала сливается каркас, затем PR в порядке зависимостей;
после слияния базового PR базу следующего меняем на main.

Ревью по кругу: Владимир проверяет Андрея, Андрей проверяет Костю, Костя
проверяет Владимира. Все участники должны быть и авторами, и ревьюерами.

Задача готова, когда выполнены требования карточки, проверки проходят,
приложение запускается, другой участник одобрил PR и код слит в main.
До слияния проверенная задача остается в In review. Подготовленный патч
не считается одобрением и не заменяет командное ревью. Для организационной
задачи без изменения файлов ветка не нужна, проверяется ее фактический результат.

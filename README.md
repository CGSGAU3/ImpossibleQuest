# Невозможный квест

Текстовый квест в Telegram. Игрок выбирает действия кнопками, меняет ход
истории и открывает концовки. Бот помнит текущую сцену, открытые концовки
и один чекпоинт на игрока.

Проект сделан для курса ТРКПО. Осенью сдаем FS, HLD, работающий продукт,
репозиторий и доску, а на зачете показываем продукт всей командой. Весной по
FS готовим системные сценарии, по HLD пишем модульные и интеграционные тесты.
Весенние тест-планы, отчеты, матрицу трассируемости и журнал дефектов сдаем
отдельно. Проверки в этом репозитории помогают ловить регрессии при разработке.

## Как запустить

Из корня репозитория на Python 3.11 или новее:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[test]'
python -m pip check
python -m pytest -q
python -m quest_bot
```

Последняя команда проверяет карту и выводит число сцен и концовок. Для запуска
бота с Telegram нужна команда `python -m quest_bot --serve` и настройки
окружения. [Настройка, сборка wheel и команды для Windows](docs/environment.md).

В чате с ботом `/start` начинает или продолжает игру, `/help` показывает
команды, `/endings` открывает прогресс по концовкам. `/save` и `/load` работают
с чекпоинтом, `/restart` начинает новое прохождение после подтверждения.
На экране концовки обе кнопки начинают новое прохождение. «Концовки» заодно
показывает список открытых концовок. Есть дополнительная пасхалка с секретной концовкой. Ее можно поискать отдельно
от прохождения обычных веток.

Карта в `quest_bot/quest.json` хранится отдельно от движка. По замечанию
к прохождению исправили одну ссылку в сцене 44. Действие «Выпутаться из
парашюта» теперь ведет в сцену 48. Исходную карту сохранили отдельно
среди материалов проекта.

## Кто за что отвечает

| Роль | Участник | Где смотреть |
| --- | --- | --- |
| А. Игровая логика и карта | Владимир (`dcfrqb`) | `models.py`, `content.py`, `story.py`, `flags.py`, `battle.py`, `minigames.py`, `drunk.py`, `lost.py`, `quest.json` |
| Б. Команды, кнопки и сообщения Telegram | Андрей (`CGSGAU3`) | `application.py`, `endings.py`, `telegram_interface.py` |
| В. Хранение, запуск и журнал | Костя (`DreamForgerGD`) | `storage.py`, `sessions.py`, `checkpoints.py`, `bootstrap.py`, `logging_config.py` |

Модули лежат в `quest_bot/`. Движок получает часы и генератор случайных чисел
при создании. Поэтому в тестах можно выставить время и повторить один и тот же
сценарий. Для хранения тесты используют отдельную SQLite, для Telegram есть
заглушки. Ручной прогон по чату делаем по [плану демо](docs/demo-checklist.md).

## Как работаем с задачами

Используем GitHub Flow. [Задачи](https://github.com/CGSGAU3/ImpossibleQuest/issues)
и [доска GitHub Projects](https://github.com/users/CGSGAU3/projects/2).

1. В карточке указываем ответственного, требования FS, разделы HLD и способ
   проверки. Когда берем карточку, назначаем себя и ставим `In progress`.
2. Делаем отдельную ветку под задачу. База обычно `main`. Если задача зависит
   от еще открытого PR, можно начать от его ветки и указать ее базой своего PR.
   Когда зависимость вольется, меняем базу на `main` и проверяем diff.
3. Передаем работу в PR. В описании оставляем ссылку на карточку, ID из FS,
   разделы HLD и результаты проверок. На доске ставим `In review`.
4. Другой участник проверяет PR и одобряет его перед слиянием. Каждый в команде
   выступает и автором, и ревьюером. Прямых коммитов в `main` нет.

### Когда ставим Done

- Закрыты требования FS и критерии из карточки.
- Проект собирается и приложение запускается. Для измененного поведения есть
  проверка, а прежние тесты проходят.
- Другой участник одобрил PR, код слит в `main`.

Для карточки без изменений в репозитории проверяем сам результат и оставляем
ссылку или запись о проверке в карточке.
